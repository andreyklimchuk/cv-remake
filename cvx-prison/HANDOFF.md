Ветка **`cvx-prison`** репозитория `andreyklimchuk/cv-remake`. Работать **только** в этой ветке и только в папке `cvx-prison/` (ветки `main`/`cv-remake` не трогать).

## Цель (требования владельца — Андрей, общаться по-русски)
Браузерный порт **Resident Evil Code: Veronica X**. Все ресурсы (комнаты, модели, анимации, тексты, звуки) берутся из **PS3-версии** игры и конвертируются. Главное правило: **всё «точь-в-точь как в оригинале», ничего не придумывать от себя** (тексты — только оригинальные, переведённые на русский; поведение — по данным игры). ## Восстановление окружения (песочница сбрасывается!)
```bash
# скачать ветку и выполнить bootstrap
curl -sL -o /tmp/b.zip https://codeload.github.com/andreyklimchuk/cv-remake/zip/refs/heads/cvx-prison && cd /tmp && unzip -qo b.zip
bash /tmp/cv-remake-cvx-prison/cvx-prison/tools/bootstrap.sh
```
bootstrap.sh делает:
- `/data/cvx/web` ← `src-ts`; `web/public/assets` собирается из `data/*.js` **только по `<script src="data/...">` из index.html** (в data/ бывают устаревшие части); ролик mv_000 — из `data/mv_000_*.js`.
- `/data/cvx/tools`, `/data/cvx/conv`; node_modules ставятся в `/data/cvxweb/node_modules` (three@0.170, vite@5, typescript, @types/three@0.170, playwright) и линкуются в `web/node_modules`.
- Образ игры (PS3 ISO, Google Drive id в скрипте) качается в `/tmp/cvxg`, распаковывается; `/data/cvx/g` → `.../USRDIR/BHCV/nativePS3`.
- **Не делает** (сделать вручную): скопировать `evt/` и `dev/` из ветки в `/data/cvx/evt`, `/data/cvx/dev`, и `cp /data/cvx/dev/* /data/cvx/` (тест-стенд ожидает файлы в /data/cvx); распаковать комнаты в `/data/cvx/ex/rmXXXX` (через tools/arc.py из `g/biocv_disc/eng/rdx_lnk/*` — так делал conv/room.py; при отсутствии ex/ room.py может распаковать сам — проверить).

## Сборка, тест, публикация
- Сборка: `cd /data/cvx/web && npx vite build` (→ web/dist).
- Тест: `cd /data/cvx && ./shotc.sh NAME t_xxx.js [scale]` — поднимает dist на :5199, headless chromium (`/usr/local/bin/chromium`, swiftshader), выполняет `t_start.js` (новая игра, пропуск ролика, `g = window.__game`) + тестовый скрипт; `return [dataURL...]` → `shots/NAME.png` (сетка), `console.log('LOG ...')` → в вывод. В тестах: `g.loop=()=>{}`, `g.sim(sec, ['KeyE',...])`, `g.enterRoom(id, spawn, undefined, false)`, `g.interact(trigger)`, `g.player.place(x,y,z,h)`.
- Публикация: `cd web && node scripts/split.mjs && cd .. && python3 tools/mkpush.py "сообщение"` → `/data/cvx/ghargs/NN.json`; затем **по одному** `GitHub.push_files(arguments_file_path=/data/cvx/ghargs/NN.json)` по порядку (последний батч — game.js+index.html). Проверка: повторный `mkpush.py` должен выдать 0 батчей.

## Что есть в игре (на коммит этой передачи)
Комнаты: rm_0000 (камера, старт), rm_0010 (коридор, машинка), rm_0020 (кладбище, зомби встают), rm_0030 (ворота тюрьмы, пистолет), rm_0050 (проход с будками, собаки), rm_0060 (казарма, карта тюрьмы), rm_0080 (гильотина, огнетушитель). Есть конвертированные, но не подключённые: rm_0021, rm_0031, rm_0040 (комната охраны, рычаг).
Таблицы в game.ts (временные «ручные» заменители логики скриптов — их нужно заменить интерпретатором evt):
- `ROOM_BY_NUM` — номер комнаты в двери → id; `ROOM_ITEMS` — какие предметы комнаты показывать; `ITEM_TRIG` — предметы без триггера; `ITEM_MSG`;
- `ROOM_ZOMBIES`, `ROOM_DOGS` — враги первого визита; `DOOR_FIX` (rm_0050 триггер 0 → дверь в rm_0030 spawn 1); `LOCK_MSG` (триггеры kind 1 = замок, сообщение (extra>>8)&0xff); `CHOICE` (вопросы Да/Нет: карта в rm_0060).
Формат триггера (room.json `triggers`): `type` hex: младший байт 1 = триггер; `(type>>8)&0xff` = вид: 0 дверь (extra: room=(e>>8)&0xff, spawn=(e>>16)&0xff), 1 замок, 3 сообщение (arg=(e>>8)&0xff), 4 предмет (arg=e&0xff). `flags`=0 — обычно управляется скриптом.
Анимации: Клэр — pl00 (mNN), нож kNN, пистолет gNN, захват зомби zNN (из en01ms, 22-костные клипы), укус собаки dNN (из en04ms: d00/d05 укус спереди/сзади, d03/d04 смерть). Зомби: Z_CLIP в enemy.ts. Собака: D_CLIP (подобрано по раскадровке — **приближённо**).

## Скрипты событий (evt) — где остановился
Файл `ex/rmXXXX/biocv_tmp/eng/data/evt/rm_XXXX.375f06da`: в начале таблица u32 смещений (n = first/4), дальше байткод скриптов, конец скрипта `ff 00` + нули.
Инструменты `evt/`: `load.py` (`all_scripts()` → {rmXXXX: [bytes,...]}), `dis.py` (обход по `Lman.json`; ключ `(op,sub)` для op из SUB={0x69,0x64,0x26,0x67}; длина `'fc'` = 2+s[p+1]; проверка if-блоков). `python3 dis.py N` — статистика и N самых частых неизвестных опкодов с контекстом. Результат: **good 1665 из 3315** скриптов разбираются полностью.

Известные команды (длина в байтах; семантика — гипотезы):
- `01 LL` if (LL от начала команды до `02`/`03 00`), `02 LL` else, `03 00` endif; `ff 00` конец.
- `04 GG II 00 00 VV` (6) проверка флага; `05 GG II 00 00 VV` (6) установка флага.
- `f8 f9 00 NN` (4) ждать NN кадров (30 fps).
- `fc LL 38 01 a b HI LO fe fd` — сообщение/реплика (HI LO — индекс или смещение текста; в rm_0030 большие значения → вероятно субтитры катсцены по mes).
- `86 ...` (16) звук; `69 07 xx xx yy yy zz zz` (8) позиция int16 мм (в rm_0030 `69 07 0898 0014 2440` = (2200,20,9280) = пистолет; `69 07 08fc 0014 2508` = (2300,20,9480) — вероятно труп en01a02); `69 0c`/`69 0d`/`69 0b` (6) — выбор сущности/поворот (`69 0b 00 5a` = 90°); `69 18 ...` (8) — вероятно запуск анимации; `65 0X YY 00` (4) — выбор объекта/персонажа.
- Остальные длины — в `Lman.json`. Следующие кандидаты: `66` (подкоманды: `66 0c`≈6, `66 08`≈8, `66 01`≈2), `33`:8, `(64,34)`:2, `93`, `2f`:4, `ca`:2, `(69,32)`:4, `4d`:4, `81`:2, `44`:6, `37`, `80`:4, `(69,1f)`:4, `10`:2, `(69,08)`:8, `(69,09)`:6. Ошибки «00» обычно из-за неверной длины соседней команды (например, `25` может быть не всегда 8).

Наблюдения по комнатам: rm_0030 enemies en62/en91/en93/en01 стоят в (0,0,0) — их ставит скрипт (en93 — Стив, en01a02 — труп охранника у пистолета). rm_0050 скрипты 17/18 двигают объекты у будок (x≈13.1/17.4 → −13.1/−17.4, z 3.0→2.15) — вероятно, дверцы будок / собаки. Катсцены используют `cut/`, `evc/`, `rmt/` (банки движений комнаты; парсер `conv/enemy.py: bank()` — track-table формат надёжнее, чем `mtn.parse3`).
